# Sprite verification captures (#272)

Committed side-by-side proof that sprite art reads at least as detailed
as the vector baseline: six scenes at 1920x1080 and 1280x720, twelve
PNG files in this directory, generated by the sprite verifier
(npm run verify:sprites).

## Scenes

- menu: full menu frame with the Play affordances and the map carousel.
- match-run-kilima: mid-match kilima frame holding run, sprite soldiers
  caught mid-stride.
- match-jet-dune: mid-match dune frame holding jet, soldiers jetting.
- frostbite-particles: frostbite frame captured with the trigger down
  under live fire plus grenade blasts, gated on particles near the
  muzzle and a bright muzzle-flash pixel in the frame itself.
- hud-kilima: live kilima frame asserting the ammo module text and
  readable name tags.
- standings: end-screen frame with the Winner callout and standings
  rows.

## Protocol

Each scene is captured at 1920x1080 then 1280x720 with a fresh arena
load and a settled sim behind it. Filenames carry the scene plus the
viewport, so the twelve files are the six scenes above times the two
resolutions. Every file must decode at the viewport in its filename
suffix and read at or above its mapped baseline: menu frames against
the menu baseline, standings frames against the standings baseline, run
and HUD frames against the kilima mid-match baseline, jet frames
against the dune theme baseline, and particle frames against the
frostbite theme baseline. Thin frames are re-taken under fire; the run
fails loudly otherwise, naming the file and both byte counts. The
inventory gate over these files runs without a browser and stays green
in CI, and the generator closes with the staged 6 MB weight tail.
